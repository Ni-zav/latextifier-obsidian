# Validation guide

## Automated

Run:

    npm install --ignore-scripts
    npm run ci

The standard suite covers:

- Markdown fragment classification;
- project/root and engine metadata;
- compiler log parsing;
- SyncTeX parsing;
- valid fragment wrappers and standalone fallback;
- recursive project indexing;
- bibliography/citation extraction;
- large include graphs and cache invalidation;
- portable HTML export;
- TypeScript/lint/production bundling.

GitHub Actions also runs a real TeX integration job that installs TeX Live and exercises:

- pdfLaTeX;
- XeLaTeX;
- LuaLaTeX;
- latexmk full bibliography builds;
- multi-file dependency discovery;
- forward SyncTeX;
- inverse SyncTeX.

CI uploads main.js, manifest.json, and styles.css as an installable plugin artifact.

## Manual Obsidian acceptance

Use a disposable vault. Manual dogfooding remains the final release gate because unit/CLI tests cannot prove Electron focus, theme, workspace, and rendering behavior.

### Markdown

1. Open a Markdown note in Live Preview and Reading view.
2. Confirm ordinary latex/tex math blocks use the fast MathJax path.
3. Enter a source block and confirm the raw block is editable.
4. Render TikZ/table/package-dependent blocks through real TeX.
5. Verify a relative include resolves from the note directory.
6. Verify switching notes does not lose cached results or leak stale output.

### TeX source editing

1. Open single-file and multi-file projects.
2. Confirm live-rendered math/theorems reveal source when the cursor enters them.
3. Confirm TikZ/table blocks render with project preamble/macros.
4. Exercise ref/cite/custom-command/environment completion.
5. Exercise TexLab completion/snippet/hover/diagnostics when TexLab is installed.
6. Verify environment closing, list continuation, brackets, dollars, comments, and Tab indentation.
7. Verify symbol palette insertion.

### Project navigator

1. Verify structure hierarchy.
2. Verify files and bibliography files.
3. Verify TODOs.
4. Verify labels and citations.
5. Search text that occurs in included files and .bib entries.
6. Change an included file outside the active tab and verify the index refreshes.
7. Open the reference graph and jump to labeled source nodes.

### PDF and compilation

1. Type rapidly and verify builds coalesce rather than overlap.
2. Introduce an error and verify the previous successful PDF remains visible.
3. Fix it and confirm scroll/page/zoom remain stable.
4. Test explicit source → PDF SyncTeX.
5. Test PDF double-click → source.
6. Enable continuous sync and scroll each pane in both directions without feedback oscillation.
7. Test zoom and fit-width after rebuilds.
8. Test a bibliography full build.

### Portable export

1. Run Export portable project HTML.
2. Disconnect networking and open the file in a browser.
3. Confirm the embedded PDF loads when a successful build existed.
4. Confirm source, outline, TODOs, refs, and citations are present.
5. Confirm source containing HTML-like text is escaped rather than executed.

### Security

1. Confirm shell escape is off by default.
2. Confirm build intermediates do not appear in the vault.
3. Confirm no network/telemetry is generated by Latextifier.
4. Confirm missing tools yield actionable errors rather than downloads.
5. Test untrusted SVG-like source and confirm generated SVG insertion remains sanitized.

## Performance acceptance

On a representative thesis-sized project:

- plugin startup spawns zero TeX processes;
- ordinary Markdown math never reaches the TeX compiler;
- only nearby PDF pages retain canvases/text layers;
- only visible source plus a bounded margin receives live-reading decorations;
- repeated identical full-LaTeX blocks reuse the fragment promise cache;
- unchanged project files reuse the ProjectIndex file cache;
- edits during an active build produce at most one queued follow-up build;
- continuous SyncTeX remains debounced and does not oscillate.

Record machine, document size, engine, warm/cold state, and debounce when publishing benchmark numbers.
